Extraction Hub

Human-in-the-loop document extraction, built on Snowflake Cortex.

Overview

Extraction Hub turns documents into trusted, structured data inside your Snowflake account. Snowflake Cortex extracts the fields you describe in plain language, a person reviews each document side by side with its data, and approved results are written to a table in your account with reviewer and timestamp. Apps graduate from full review to automated pipelines where your team only handles exceptions.

Everything runs inside your Snowflake account using Snowflake Cortex. Your documents and extracted data never leave your account, the application makes no external network calls, and the provider never receives your data.

Install and setup

Install Extraction Hub from the Snowflake Marketplace listing, then open the Extraction Hub Streamlit from the app tile (pick a warehouse when prompted on first launch).

Grant the application access to Cortex, your document stage, and a results schema. Run these as ACCOUNTADMIN (replace the placeholders with your objects and the installed application name). The in-app Setup & access panel shows these with your app name filled in, and Run diagnostics checks each grant and prints the exact fix for anything missing.

-- Required: lets the app call Snowflake Cortex AI functions.
-- (CORTEX_USER is a database role; the consumer grants it to the application -
--  it cannot be requested in the app manifest.)
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO APPLICATION <app_name>;

-- Let the app read your document stage:
GRANT USAGE ON DATABASE <db> TO APPLICATION <app_name>;
GRANT USAGE ON SCHEMA  <db>.<schema> TO APPLICATION <app_name>;
GRANT READ  ON STAGE   <db>.<schema>.<stage> TO APPLICATION <app_name>;

-- Let the app create and write its output table(s):
GRANT USAGE, CREATE TABLE ON SCHEMA <db>.<results_schema> TO APPLICATION <app_name>;

Five removable example apps (Finance, Operations, Purchasing, HR, Legal), each with a sample document, are preloaded so you can try the full workflow immediately.

Create an extraction app

Select New extraction app, point it at your document stage and an output table, and add the fields to extract. Each field is a name plus a plain-language question, for example "Invoice number" or "What is the total due?". Per field you can:

  • Extract a value - pull a value from the document.
  • Categorize it - classify into categories you define.
  • Gauge sentiment - positive / neutral / negative.

Sharing one stage across several apps? Use the file-name filter so each app only sees its own files. No AI or function knowledge is required.

Review documents

The document appears next to an editable form laid out in reading order, with per-field confidence scores. Detected tables (like invoice line items) become editable grids. Correct anything, then mark it reviewed - the record locks, and every change lands in an append-only audit log. An explicit "Unlock to correct" step is required to change a reviewed record. The queue offers "To review / Skipped / All" views and advances to the next document on save.

Automation and the maturity path

Every app moves through three stages you control from the Admin Dashboard's Automation tab:

  • Review - people verify every document (the default).
  • Assisted - confident documents are written automatically; the rest queue for review.
  • Autopilot - straight-through processing; people only handle the Exceptions queue, where each document shows why it needs a look (low-confidence fields, empty result, or a failure).

Promotion is evidence-based: the app measures how often the AI's extraction matched what your reviewers approved and tells you when an app is ready. Runs are on-demand today via Run now; scheduled runs arrive in a future release.

Snowflake Cortex usage

The app calls these Snowflake Cortex functions, all executed inside your account:

  • AI_EXTRACT - primary single-document extraction (values plus per-field confidence where supported).
  • AI_PARSE_DOCUMENT - parses each document to text/layout (also used to detect tables).
  • AI_COMPLETE - fallback and multi-record extraction. Default model: snowflake-llama-3.3-70b.
  • AI_CLASSIFY - for fields configured as "Categorize it."
  • SENTIMENT - for fields configured as "Gauge sentiment."

Regional availability: if snowflake-llama-3.3-70b is not hosted in your region, enable Snowflake cross-region inference once as ACCOUNTADMIN and extraction works normally:

ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';
-- (or a specific region group per your data-residency policy)

Cortex usage consumes credits in your account. The app shows an estimated call count before bulk extraction, and admins can set budgets and rate limits in the Admin Dashboard.

Output objects

Each app writes to the output table you configure. Reserved columns added to every output table:

ColumnTypeDescription
FILE_NAMEVARCHARSource document file name (stage basename).
<your field columns>VARCHAROne column per configured field. Extracted or corrected text.
IS_REVIEWEDBOOLEANTRUE once a human reviewed and approved the row.
REVIEWER_USERNAMEVARCHARSnowflake user who marked the row reviewed.
REVIEW_TIMESTAMPTIMESTAMP_NTZWhen the row was marked reviewed.
PROCESSED_ATTIMESTAMP_NTZWhen the row was written.
RECORD_IDVARCHARUnique id per saved row.
SOURCE_APPVARCHARExtraction app that produced the row.
STATUSVARCHARapproved, needs_review, auto_written, or flagged.
ORIGINVARCHARmanual (human save) or pipeline (automated).
CONFIDENCEFLOATAverage AI confidence for the document (0-1).
EXCEPTION_REASONVARCHARWhy the pipeline sent the document to a human.

Companion objects created per app:

  • <table>_TYPED - trusted analytics view (approved or confidently auto-written rows only; numbers and dates cast to real types). Point dashboards at this view.
  • <table>_TABLES - one row per detected document table (line items).
  • CONFIG.AUDIT_LOG - append-only log of every draft, review, and re-run with old and new values.
  • CONFIG.PIPELINES / CONFIG.PIPELINE_RUNS - per-app automation config and run history.
  • CONFIG.USAGE_EVENTS - per-extraction usage records powering the admin cost dashboard.

Free trial

Marketplace trials include every feature for 30 days, capped at 100 documents (counting human-reviewed documents and documents processed by automation). The hub shows your usage; at the limit, reviewing and automation pause until purchase. Your apps, configuration, and data carry over unchanged when you purchase.

Data handling

  • Documents are read from your stage and processed entirely within your Snowflake account; the app has no external network access and sends nothing to the provider.
  • The provider never receives your documents or extracted data.
  • Preloaded example documents are synthetic (no real personal data).
  • Per-group role settings control visibility in the app UI only - to truly restrict sensitive documents, also grant the underlying stage and output tables only to the appropriate roles in Snowflake.
